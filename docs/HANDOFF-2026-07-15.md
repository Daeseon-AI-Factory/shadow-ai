# MiMi — Codex 작업 핸드오프 (2026-07-15 현재 기준)

> 세션 컨텍스트 한계로 남기는 스냅샷. "지금 뭐가 됐고, 뭘 정해야 하고, Codex한테 뭘 던질지" 전체.

## 0. 현재 상태 (사실)
- **TestFlight build 22 (iOS)** = U1~U4 통합(홈 익힘요약 · 세션 진행바·peak-end · 팩 진행바·마일스톤) + **카드 글자 잘림 고침**. Apple 처리 후 설치 가능.
- 브랜치 **`integration/tracks`** (origin, HEAD 94f7a1b)에 모바일 작업 다 있음.
  - ⚠️ `origin/main` 대비 **main +79 / integration +12** 로 크게 갈라짐(main엔 웹 작업 등). 통합 미해결.
- **AI 게이팅 활성**: 무료 유저 AI 호출 → 403(AI_NOT_ALLOWED). 통과 = 유료 or allowlist(owner). deny-by-default(`AiGate`).
- **수금 경로 없음**: 모바일 IAP SDK 없음, 실제 결제 프로세서 미연동. 백엔드 billing은 배관만(webhook + `User.plan` + `BillingService`).
- 백엔드: Vultr, `api.mimi.daeseon.ai`. **자체 Spring JWT auth**(`com.tubeshadow.auth`) — **Supabase 아님**.
- Android: app.json에 설정 완비(package `ai.daeseon.mimi`, adaptive icon, RECORD_AUDIO 권한). **아직 빌드·테스트·스토어 안 함.**

## 1. 착수 전 정해야 할 결정 (사용자만 가능 — Codex 못 함)
- **D1 — 수익화 방식**
  - (a) **iOS/Android IAP (RevenueCat)** — 앱내 판매, 애플/구글 15~30% 수수료. 표준·안전·전환률↑. **권장.**
  - (b) **웹판매 + reader 모델** — 프리미엄은 웹(Lemon Squeezy 플랫폼)에서 팔고, 앱은 entitlement 조회로 **unlock만**(앱에선 결제 언급·링크 금지). 애플컷 회피 but 전환률↓ + 애플 심사 리스크.
  - (c) 보류.
  - ⚠️ **어느 경우든 Lemon Squeezy "웹 체크아웃 버튼"을 iOS/Android 앱 안에 넣으면 스토어 리젝**(Apple 3.1.1 / Google 유사).
- **D2 — Auth**: 자체 Spring JWT 유지(플랫폼 `api.daeseon.ai`이 mimi JWT를 받게 어댑터) vs **Supabase 이관**(플랫폼 표준에 맞춤, 큰 공사). *플랫폼 결제 연동하려면 이거 먼저 풀려야.*
- **D3 — 판매 형태**: 앱(모바일) 중심 판매 vs 웹 병행. (코어 경험=쉐도잉·실시간 스피킹이라 모바일이 맞음 → **앱+IAP 추천**)
- **D4 — 브랜치 통합 목적지**: `integration/tracks`(모바일 12커밋)를 `main`(웹 79커밋)과 어떻게 합칠지. 지금 갈라져 있어 릴리즈 전 반드시 정리.

## 2. Codex 트랙 (병렬 단위)

### A. 즉시 착수 가능 (결정 불필요)
- **M — 메뉴 재편** *(설계 확정됨)*
  - 탭바 → `홈 · 쉐도잉 · [스피킹] · 영작 · 나`. `practice`·`review`는 탭에서 내리고(href:null), `videos`(쉐도잉)·`compose`(영작)를 탭으로 승격. 스파링 센터 유지.
  - **홈 허브화**: 최상단 ⭐"오늘 복습 N개"→`/review` + "연습 자료"→`/practice`(기존 그리드 통째 유지) + U2 익힘요약·최근클립 유지.
  - **연습팩 15종 = 참조로 격하(삭제 0)**. 모든 라우트 살림.
  - 파일: `(tabs)/_layout.tsx`, `(tabs)/index.tsx`, `videos.tsx`·`compose.tsx`(탭화), i18n.
  - 수용: 5탭·복습 홈최상단·전 라우트 유지·tsc0·light/dark.
- **AND — Android 실동작/빌드**
  - `expo-symbols` Android 폴백 전 화면 검증(심볼 객체에 `android:` 있음 — 깨지는 곳 확인), SafeArea·탭바·폰트·오디오권한 Android 확인.
  - `eas build --platform android --profile production` (로컬빌드 가능, 크레딧 주의).
  - 수용: Android 실기기/에뮬 부팅 + 로그인·쉐도잉·스파링·복습 동작 + 심볼 정상.

### B. 결정 후 착수 (D1/D2 blocked)
- **PAY — 수익화** *(D1·D2 확정 후, 수금 켜기 = 최우선)*
  - D1=(a)면: **RevenueCat SDK**(iOS+Android IAP) + paywall UI(현 invite-only 패널 대체) + `AiGate` 유료판정을 RevenueCat/플랫폼 entitlement에 연결 + RevenueCat webhook → `api.daeseon.ai` 동기화.
  - D1=(b)면: 앱은 `/v1/entitlements` 조회로 unlock만(결제 UI·링크 없음, reader 모델).
- **MV — My Voice** *(D2 auth·백엔드 확인 후 — 최고 레버리지 기능)*
  - 웹(`faangforge.daeseon.ai/myvoice`) 로직 모바일 포팅: **한글→상황맞는 영어 생성** + **배운 영어 저장** + **자산 축적** + **복습(SRS) 연동**. 탭 자리 = 지금 임시 compose, 여기로 채움.
  - 영작(GAME)과 관계: **My Voice=은행(축적·복습소스), 영작/쉐도잉/스피킹=입금 소스**. 합치지 말고 저금 흐름으로.

### C. 스토어 출시 준비 (병렬)
- **STORE-iOS**: App Store 심사 메타/스크린샷/개인정보/심사노트 (`mobile/APP_STORE_REVIEW.md` 있음, `app-store-screenshots/` 있음).
- **STORE-AND**: Play Console 앱 등록·Play App Signing·콘텐츠 등급·데이터 안전·스크린샷.

### D. 후속 (설계 방향만 있음)
- **GAME — 영작 게임화**: 자유타이핑 → 조각씩 구조 구성 게임. **패턴팩(english-patterns 300·it-patterns)을 뼈대로.** 핵심 = "문법 구조 이해"(타일 배열 금지). *설계 더 필요.*
- **DISC — discover 부활**: 쉐도잉 콘텐츠 발견 피드(`discover.tsx` 존재) → 원탭 임포트.
- **ONB — 온보딩/빈상태**: 첫 유저(클립0·카드0) 홈 첫 행동 유도.
- **INT — 모의면접 전면화**: 창업자 킬러 유스케이스(캐나다 개발자 잡). 스파링 interview 모드를 눈에 띄게.

## 3. 추천 순서
1. **지금 결정**: D1·D2·D3·D4.
2. **양 플랫폼 현재버전 배포** (사용자 목표): `M`(메뉴) 원하면 먼저 or 스킵 → **`AND`(안드로이드 실동작)** → `STORE-iOS`/`STORE-AND` → iOS·Android 동시 제출.
3. **`PAY`(수익화)** — D1/D2 후 최우선(수금 켜야 의미).
4. **`MV`(My Voice)** — 최고 레버리지 신기능.
5. `GAME` → `DISC` → `ONB` → `INT`.

## 4. 지뢰/주의
- Lemon Squeezy 웹결제 = **웹 제품용**. iOS/Android 앱 안에 넣지 마라(스토어 리젝).
- 플랫폼 결제 스펙은 **Supabase JWT 전제** → mimi는 자체 JWT라 **D2 안 풀면 못 붙음**.
- `integration/tracks` ↔ `main` 갈라짐(12/79) — 릴리즈 전 D4 통합 필수.
- EAS 클라우드 빌드 **이달 무료분 소진(8/1 리셋)** → 그때까진 `--local` 빌드(fastlane 설치돼 있음).
- 로그 규칙: 커밋마다 `docs/troubleshooting.md` + `content/logs/shadow-ai/*.mdx` (CLAUDE.md).
