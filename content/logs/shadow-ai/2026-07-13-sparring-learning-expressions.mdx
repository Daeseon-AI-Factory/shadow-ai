## 문제

기존 스파링은 due 카드를 먼저 고른 뒤, 미래 예정 카드를 숙련도와 상관없이 한꺼번에
섞었다. 방금 배우는 box 1 표현과 이미 더 익숙한 표현을 구분하지 않아, “요즘 배우는
표현만 대화로 연습”하는 선택지가 없었다.

## 구현

공유 core의 `partitionLearning`이 다음 두 묶음을 만든다.

- **learning:** `box <= 1`이고 복습일이 아직 오지 않은 카드. box가 낮고 정답 횟수가 적은 순.
- **fresh:** 아직 SRS 상태가 없는 카드.

스파링의 **신규 학습 표현** 주제는 learning을 우선 넣고 여섯 자리가 차지 않으면 fresh로
채운다. `SrsCard`에는 생성 시각이 없으므로 “최근”을 임의의 시간 순서로 가장하지 않고,
백로그가 정의한 낮은 box와 미도래 날짜를 기준으로 삼았다. 오늘 복습의 기존 due→known
선택 경로는 변경하지 않았다.

## 검증 범위

Node 24로 실제 TypeScript helper를 import해 낮은 box 우선순위, 오늘 due 제외, box 2 제외,
fresh 보충, 동률 원본 순서, 입력 불변성을 assertion으로 확인했다. 출력은 다음과 같았다.

```text
partitionLearning checks: ordering, boundaries, fresh, stable ties, input immutability passed
```

`cd mobile && npx tsc --noEmit`도 출력 없이 exit 0이었다. 실제 화면에서 선택한 모드가
서버 SRS 데이터와 함께 표시되는지는 최종 iOS 개발 빌드에서 별도 확인한다.
