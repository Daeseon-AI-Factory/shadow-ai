## 무엇을 했나

NCP(네이버 클라우드, 서울) 크레딧이 소진돼 Vultr 서울 박스(158.247.241.199)로
서비스를 이관했다. MiMi 백엔드는 이 세션에서 직접 이관했고(도커 이미지 빌드 →
`/opt/mimi-app` 독립 스택 → 기존 `ds-forge-caddy` 프록시에 라우팅 → DNS 컷오버),
jjan·beside·docvault는 병렬로 다른 에이전트(Codex)가 이관·검증했다. 검증 후 NCP를
`terraform destroy` + API로 폐기했다.

## 얻은 교훈 (아프게)

**1. "다 껐다"를 리소스 하나 보고 단언하지 마라.**
`terraform destroy`로 MiMi 박스를 지운 뒤 "NCP 전부 껐다"고 말했는데, NCP 계정엔
terraform이 모르는 **별도 배포(beside 서버 + 관리형 DB + Object Storage + 공인IP)**가
그대로 돌며 과금되고 있었다(월 추정 12,320원). `terraform destroy`는 **terraform state에
있는 것만** 지운다. 계정 전체가 0인지는 반드시 API/콘솔로 **계정 단위 조회**로 확인해야
한다(`getServerInstanceList`, `getBlockStorageInstanceList`, `getPublicIpInstanceList`,
`getCloudPostgresqlInstanceList`, S3 `ls`).

**2. 마운트된 블록 스토리지는 서버가 떠 있으면 못 지운다.**
실제 에러:
```
Status: 400 Bad Request ... returnCode: 3001008
"1 storage returns failed. mimi-data(...) : The storage is mounted on the server.
 Please unmount the storage and try again."
```
`terraform destroy`가 block_storage를 server보다 먼저 지우려다 실패. 게다가 공인 IP를
이미 반납한 뒤라 SSH로도 못 들어가 언마운트 불가. 해결: **NCP API로 서버를 먼저 정지**
(`stopServerInstances`) → 정지 확인 → `terraform destroy` 재실행. 그러면 디스크가 풀려
정상 삭제된다. 순서: 서버 정지 → 스토리지 → 서버 반납.

**3. JWT_SECRET을 새로 만들면 기존 로그인 세션이 전부 무효화된다.**
새 박스 `.env`에 JWT_SECRET을 새로 생성했더니, 앱에 저장된 옛 토큰(옛 서명키)이 거부됐다.
증상: "앱 켜면 한참 있다가 로그인창." 원인: 앱이 저장된 토큰으로 부팅 → 홈에서 첫 API
호출 → 서버가 401 → `signOut` → `/login`. 그 왕복(캐나다↔서울 ~0.5초)이 지연으로 체감됨.
비번은 bcrypt라 그대로 유효 → **한 번 재로그인하면 새 서명키 토큰을 받아 해소**. 세션
연속성을 지키려면 이관 시 JWT_SECRET을 보존해야 한다.

## 검증

- MiMi: 공개 HTTPS로 `/api/health` 200, `/sparring.html` 200, 실제 gpt-realtime 세션 발급 성공(signup→mint), 검증 계정 정리.
- beside: Vultr에서 DB 6테이블 + 사진 2개(`/opt/beside/data/media`) 실재 확인 후에야 NCP 폐기.
- NCP 최종: 서버 0 / 블록스토리지 0 / 공인IP 0 / 관리형 PostgreSQL 0 / 버킷 0.
